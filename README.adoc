= Incus Profiles

Personal profiles for https://linuxcontainers.org/incus/[Incus].

The GUI profile is intentionally generated from the current host login session. Wayland, X11, D-Bus, PipeWire, and Pulse sockets live under runtime paths such as `/run/user/$UID`, so hardcoding those paths in committed YAML makes new instances fragile.

== Layout

`profiles/`: importable fallback profiles and profile contents.

`scripts/`: host-aware profile generators (see also NixOS Guests below).

`base/`: small reference fragments.

== Fresh Minimal Setup

----
# incus admin init --minimal
----

== Apply Profiles

Generate the GUI profile from the active desktop session:

----
$ ./scripts/apply-gui-profile.sh
----

The script creates the profile if needed and replaces the existing profile contents. Preview the generated YAML first with:

----
$ DRY_RUN=1 ./scripts/apply-gui-profile.sh
----

A full example of the generated `gui` and `osu` profiles is in link:examples/generated-profiles.adoc[examples/generated-profiles.adoc].

Generate the osu! profile:

----
$ ./scripts/apply-osu-profile.sh
----

By default, the osu! profile mounts `$HOME/osu` when that directory exists. Override it with:

----
$ OSU_SOURCE=/path/to/osu ./scripts/apply-osu-profile.sh
----

== NixOS Guests

`apply-gui-profile.sh` does half its work through `cloud-init.vendor-data`: the guest user, the runtime directory, the socket symlinks, and the `/etc/profile.d` exports. NixOS container images do not ship cloud-init, so on a NixOS guest all of that is silently ignored and only `devices:` takes effect.

Use the NixOS variant instead:

----
$ ./scripts/apply-nixos-gui-profile.sh
$ DRY_RUN=1 ./scripts/apply-nixos-gui-profile.sh   # preview
----

It performs the same host-session discovery and accepts the same overrides, but emits session variables as `environment.*` instance keys rather than profile.d exports -- which also means a non-login `incus exec` sees them -- and no cloud-init at all.

This script only passes things in. Everything cloud-init would have done is the guest's own responsibility, declared however that distribution prefers:

* define the guest user with uid `GUEST_UID`
* create `/run/user/$GUEST_UID` owned by that user
* link the mounted sockets to the names clients expect there -- `wayland-0`, `pipewire-0`, and `/tmp/.X11-unix/X0`
* install GPU userspace (Mesa) and fonts

Both halves are required; neither works alone.

Guest socket paths are normalized, unlike in `apply-gui-profile.sh`:

[cols="1,1,1"]
|===
| Host | Guest mount | Guest symlink

| `$XDG_RUNTIME_DIR/wayland-N`
| `/mnt/.sockets/wayland`
| `/run/user/$GUEST_UID/wayland-0`

| `/tmp/.X11-unix/XN`
| `/mnt/.sockets/x11`
| `/tmp/.X11-unix/X0`

| `$XDG_RUNTIME_DIR/pipewire-0`
| `/mnt/.sockets/pipewire`
| `/run/user/$GUEST_UID/pipewire-0`

| `$XDG_RUNTIME_DIR/pulse/native`
| `/mnt/.sockets/pulse-native`
| (used directly via `PULSE_SERVER`)
|===

No host display number reaches the guest, so the guest's half is identical whether the compositor came up on `wayland-0` or `wayland-1`. `GUEST_UID` must match the guest user's uid, and it should be pinned there rather than left to whatever `useradd` allocates -- the `gpu` device ownership and the runtime directory path both depend on it.

Session D-Bus is not passed through, so desktop portals are unavailable.

Launch with your own NixOS image rather than one from `images:`, since these are built locally:

----
$ incus launch <nixos-image> <instance> --profile default --profile nixos-gui
----

== Launch

Cloud-init package installation only runs during the instance's first boot. Importing or editing a profile does not retroactively install packages into an existing instance whose cloud-init already ran.

The simplest path is:

----
$ ./scripts/launch-osu.sh
----

That script applies the generated profiles first, then launches the cloud image with the profiles attached.

Manual equivalent:

----
$ incus launch images:archlinux/cloud osu --profile default --profile gui --profile osu
----

If you launch the image without `--profile gui --profile osu`, the profile cloud-init config is not present at first boot and the packages from `profiles/osu.yml` will not be preinstalled.

== Useful Overrides

The scripts default to a guest user named `chicken` with UID/GID `1000`.

----
$ GUEST_USER=chicken GUEST_UID=1000 GUEST_GID=1000 ./scripts/apply-gui-profile.sh
----

Optional devices are disabled by default:

----
$ INCLUDE_CAMERA=1 ./scripts/apply-gui-profile.sh
$ INCLUDE_SYSTEM_DBUS=1 ./scripts/apply-gui-profile.sh
----

If your audio session uses a nonstandard socket path:

----
$ PULSE_SOCKET=/run/user/1000/pulse/native ./scripts/apply-gui-profile.sh
$ PIPEWIRE_SOCKET=/run/user/1000/pipewire-0 ./scripts/apply-gui-profile.sh
----
